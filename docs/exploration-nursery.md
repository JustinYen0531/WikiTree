# WikiTree 探索苗圃

探索苗圃會定時把外界素材帶進 WikiTree，但不會自行改動正式筆記。完整流程是：

`建立探索任務 → 素材進入苗圃 → 挑進來源籃 → AI 整理草稿 → 預覽 → 建立新葉片或插入現有筆記`

## 第一次使用

1. 在專案資料夾執行 `npm install`，再執行 `npm run dev`。
2. 在 WikiTree 的 FOREST 連接一個 Windows 本機資料夾。
3. 到 `ORBIT → 探索苗圃`，按「建立探索任務」。
4. 填寫任務名稱、自由探索題目、AI、來源、數量與節奏。
5. 若希望關閉 WikiTree 後仍可定時探索，按左下角「安裝」背景排程。

通知預設關閉；即使不開 Windows 通知，WikiTree 內的未讀數仍會保留。電腦關機、未登入或離線時，該次排程會直接略過，不會在下次開機補跑。

## 素材與正式筆記的界線

- 每筆素材都會標成「AI 自動排程探索」。
- 「來源支持的內容」與「AI 整理／推論」會分開顯示。
- 來源是可參考、可質疑的材料，不是 RAG，也不是絕對事實。
- 來源籃最多 10 筆，可跨不同任務與執行批次挑選。
- 送到 AI 工作台只會建立草稿對話，不會寫入筆記。
- 草稿預覽後，必須由你選擇「建立新葉片」或「插入現有筆記」。
- 新筆記會要求 AI 加上 `origin`、探索任務、探索執行與來源 ID。

## 本機資料位置

探索資料位於：

`%LOCALAPPDATA%\WikiTree\exploration-v1`

每個 WikiTree 工作區會分開保存。排程結果不會寫入 Markdown 資料夾，也不會讓知識森林的 Git 出現自動產生檔案。AI 連線沿用 WikiTree 既有登入，不會匯入舊 Brew 的 API Key、Supabase 帳號或匿名登入資料。

## 從舊 Brew 匯入

左下角可選擇「從舊 Brew 匯入」。它只會在你主動指定資料夾後執行：

- 讀取日期命名的歷史 JSON。
- 忽略 `latest.json` 這個重複入口。
- 以日期與整理後網址去除重複。
- 舊資料預設為已讀、封存，避免突然灌滿未讀素材。
- 不會讓 WikiTree 執行時依賴舊 Brew 資料夾。

## 不花模型額度的本機驗收

```powershell
npm run check:exploration
npm run build
```

測試會使用 `fixtures/exploration/mock-run.json`，涵蓋資料隔離、網址防護、去重、短缺、假時鐘排程、一次重試、來源籃與筆記交接，不會呼叫真實 AI 或真實搜尋。

## 常見狀況

- 「背景排程尚未安裝」：按「安裝」；若失敗，畫面會顯示 Windows 回傳的真實錯誤，可再按一次重試。
- OpenAI 沒有真的搜尋：即使程式支援受限制搜尋，實際是否可用仍受模型、帳號、網路與管理政策影響。
- 素材少於目標數量：這是刻意行為。網址、日期或來源無法確認時，系統會保存較少結果並標記原因。
- 換了知識森林卻看不到原本素材：探索資料依工作區隔離，這代表保護正常生效。
